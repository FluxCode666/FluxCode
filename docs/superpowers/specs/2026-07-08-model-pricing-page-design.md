# 模型定价页设计

## 背景

当前系统已有两套和价格相关的能力：

- 远程模型价格服务会拉取 `model_pricing.json`，并通过 `PricingService` / `BillingService.GetModelPricing(model)` 提供官方基础价。
- 渠道管理中的 `channel_model_pricing` 可以为渠道关联分组配置模型列表、计费模式、token 价格、按次价格、图片价格和区间价格。

已有公开 `/pricing` 页面展示的是“定价方案/套餐”卡片，不是模型价格。用户现在需要一个新的官网模型定价页：首页按模型展示列表，点击模型后展示详情，列出支持该模型的分组价格和相对官方价格倍率。同时需要在官网顶部菜单和控制台侧边栏增加入口，控制台入口跳转到同一个官网公开页面。

旧“定价方案”展示系统不再需要。本次移除它的前后端运行时代码和菜单入口，但保留购买订阅、支付套餐和订单管理能力。

## 目标

1. 新增公开模型定价页 `/model-pricing`。
2. 复用渠道管理页作为模型展示、支持范围和特殊定价的唯一维护入口。
3. 模型列表来自启用渠道的 `model_pricing.models`，不新增公开模型目录管理。
4. 模型详情只展示支持该模型的分组；不支持的分组直接隐藏。
5. 价格展示与实际计费解析保持一致，并展示相对官方价格倍率。
6. 渠道模型定价支持配置展示用能力标签：对话、图片、视频。
7. 模型定价页提供搜索框，输入查询带防抖。
8. 官网顶部菜单和控制台菜单增加“模型定价”入口。
9. 彻底移除旧“定价方案”前后端功能入口和运行时代码。
10. 保留 `/purchase`、支付套餐、订阅购买、订单管理和管理员订单套餐。

## 非目标

1. 不新增公开模型白名单或模型目录管理页。
2. 不让能力标签参与模型调用、账号选择、路由、限制或计费。
3. 不在用户页面展示“渠道定价”“官方倍率”“特殊定价”等后台来源标签。
4. 不自动从远程 `model_pricing.json` 同步写入 `channel_model_pricing.models`。
5. 不在本次删除 `pricing_plan_groups` / `pricing_plans` 数据库表。
6. 不改造支付套餐、订阅购买、充值订单或管理员订单套餐。

## 方案选择

采用“复用渠道管理页”的方案。

渠道管理页本身已经表达了两个关键事实：某个渠道关联哪些分组，以及这个渠道支持哪些模型和特殊价格。每个分组最多属于一个渠道，因此模型详情页可以稳定地从“分组所属渠道 + 渠道模型定价”推导该分组是否支持模型。

先前考虑过新增公开模型目录，但那会导致两套维护：账号/渠道里维护实际支持模型，模型目录里再维护展示支持分组。最终选择不新增这套目录，避免长期不同步。

## 数据模型

### 渠道模型定价能力标签

在 `channel_model_pricing` 增加 `capabilities`：

- 类型：`JSONB NOT NULL DEFAULT '[]'`。
- Go / DTO / TypeScript 类型：`string[]`。
- 允许值：
  - `chat`：对话
  - `image`：图片
  - `video`：视频
- 语义：仅用于公开模型定价页展示。
- 不参与网关请求、模型限制、模型映射、账号调度、实际计费或统计计算。

一个定价条目可绑定多个模型，条目上的能力标签由这些模型共享。若同一个具体模型通过多条配置命中多个能力标签，公开展示时取去重合集。

### 旧定价方案表

本次不新增 drop 迁移，不删除 `pricing_plan_groups` / `pricing_plans` 表，避免破坏历史数据和回滚路径。只移除运行时代码入口和前端入口。

## 后端设计

### 渠道 CRUD 扩展

渠道管理相关请求、响应和 service 类型增加 `capabilities` 字段：

- `channelModelPricingRequest.capabilities`
- `channelModelPricingResponse.capabilities`
- `service.ChannelModelPricing.Capabilities`
- 前端 `ChannelModelPricing.capabilities`

创建、更新、查询渠道时保留该字段。未传时按空数组处理。需要过滤空字符串和重复值，只保留允许值。

### 公开模型定价接口

新增公开只读接口：

- `GET /api/v1/model-pricing/models`
- `GET /api/v1/model-pricing/models/:model`

列表接口支持查询参数：

- `q`：搜索关键词，匹配模型 ID、展示名、平台或能力标签。
- `platform`：可选平台过滤。
- `capability`：可选能力标签过滤。

前端可先加载全量后本地过滤；若接口返回量较大，使用 `q` 做服务端过滤。无论哪种实现，前端搜索输入都使用 300ms 防抖。

### 聚合规则

模型列表来源：

1. 遍历启用渠道。
2. 遍历每个渠道的 `model_pricing`。
3. 展开 `models` 中的具体模型。
4. 通配符模型如 `claude-*` 可用于详情支持判断，但不作为列表中的公开模型项直接展示。
5. 如果官方价格服务查不到该模型价格，但渠道配置了至少一个手动价格字段或有效区间价格，则模型仍进入公开列表；既无官方价也无手动价时不展示。
6. 如果模型没有任何可展示分组，则不进入公开列表。

模型详情分组支持规则：

1. 分组必须为 active。
2. 分组必须属于启用渠道。
3. 分组所属渠道的 `model_pricing.models` 必须命中该模型。
4. 命中规则复用现有渠道匹配逻辑：精确匹配优先，通配符按配置顺序匹配。
5. 不支持的分组直接隐藏。

价格计算规则：

1. 优先从官方价格服务取得基础价；官方价格不存在时使用空基础价，并要求渠道提供手动价格。
2. 若渠道模型定价命中该模型，则按现有解析规则用非空渠道字段覆盖基础价。
3. 渠道价格字段为空时，保留官方基础价；官方价也不存在时该字段显示为空。
4. 最终展示价格乘以分组 `rate_multiplier`。
5. 如果存在用户专属分组倍率，本公开页不按具体用户定制；只展示分组默认倍率。
6. 相对官方价格倍率按最终展示价除以官方价计算，按字段分别计算。

计费模式展示：

- `token`：展示输入、输出、缓存写入、缓存读取、图片输出 token 价格；有区间时展示区间价格。
- `per_request`：展示默认单次价格和层级价格。
- `image`：展示默认图片价格和图片层级价格。

公开接口返回的是展示模型，不暴露“渠道定价”“特殊定价”等来源标签。内部可以保留来源字段用于测试或调试，但不得返回给用户页面。

### 错误处理

- 官方价格不可用：有手动渠道价格时继续展示，官方价格和无法计算的倍率显示为空；没有任何手动价格时过滤该模型。
- 没有启用渠道或没有模型定价：返回空列表。
- 搜索查询失败：接口返回正常错误码，前端提示“查询异常”并提供重试。
- 聚合过程中单个模型异常不应导致整个列表失败；可以跳过异常项并记录日志。

## 前端设计

### 模型定价页

新增 `ModelPricingView.vue`，路由为 `/model-pricing`。

页面首屏就是可用模型列表，不做营销落地页。顶部提供：

- 搜索框。
- 平台筛选。
- 能力标签筛选。

搜索框行为：

- 输入模型 ID、展示名、平台或能力标签可查询。
- 300ms 防抖。
- 搜索中保留平台和能力筛选条件。
- 搜索为空时恢复默认模型列表。
- 搜索请求失败时展示“查询异常”，并提供重试按钮。
- 无结果时展示“未找到匹配模型”。

模型卡片展示：

- 模型名。
- 平台。
- 能力标签。
- 支持分组数量。
- 官方基础价格摘要。

点击模型进入详情。可以采用同一路由 query 或子路由，例如 `/model-pricing/:modelId`。

### 模型详情

详情页展示：

- 模型名。
- 平台。
- 能力标签。
- 官方价格。
- 支持该模型的分组价格表。

分组价格表字段：

- 分组名。
- 分组倍率。
- 输入价。
- 输出价。
- 缓存写入价。
- 缓存读取价。
- 图片输出价或按次价格。
- 相对官方价倍率。

若模型有 token 区间、按次层级或图片层级，详情页使用展开行展示。用户页面不展示价格来源标签。

### 导航入口

官网顶部菜单新增“模型定价”，跳转 `/model-pricing`。

控制台侧边栏新增“模型定价”，用户和管理员都可见，点击跳转同一个 `/model-pricing` 公开页。

### 渠道管理页能力标签

在 `PricingEntryCard.vue` 的模型定价条目中新增能力标签多选：

- 对话
- 图片
- 视频

标签只影响公开展示。保存渠道时随 `model_pricing` 提交。

当前前端添加模型时会尝试拉官方价并自动填入价格字段。这个行为可以保留：显式保存官方价等价于以当前官方价为基础定价。若未来需要自动跟随官方价变化，可以另行增加“使用官方价”开关或允许清空价格字段。

## 旧定价方案移除

前端移除：

- `/pricing` 路由和旧 `PricingView.vue`。
- 旧公开套餐定价页面测试。
- `pricingPlansAPI`。
- 管理员 `/admin/pricing-plans` 菜单和页面。
- 旧 `PricingPlansView.vue` 及相关测试。

后端移除：

- 公开 `/api/v1/pricing/plan-groups`。
- 管理 `/api/v1/admin/pricing/plan-groups`。
- 管理 `/api/v1/admin/pricing/plans`。
- pricing plan handler、service、repository、DTO、routes 和测试引用。

保留：

- `/purchase` 用户购买订阅页。
- `/orders` 用户订单页。
- `/admin/orders/plans` 管理员支付套餐页。
- `/api/v1/payment/plans` 等支付/订阅购买接口。
- 支付、订阅和订单相关数据库表。

## 验收标准

1. 官网 `/model-pricing` 显示来自启用渠道模型定价的模型列表。
2. 模型搜索带防抖，查询失败时提示“查询异常”。
3. 模型卡片显示平台、能力标签、支持分组数量和官方价格摘要。
4. 模型详情只展示支持该模型的分组。
5. 价格与现有计费解析一致：官方价、渠道覆盖价和分组倍率组合正确。
6. 相对官方价倍率展示正确。
7. 渠道管理页可为模型定价配置对话、图片、视频能力标签。
8. 能力标签不影响实际调用、路由、模型限制或计费。
9. 官网顶部菜单和控制台菜单都有“模型定价”入口。
10. 旧“定价方案”公开页、管理页和后端接口不可用。
11. 购买订阅、支付套餐和订单管理功能不受影响。
